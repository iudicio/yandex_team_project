## Порядок приоритета

Если источники расходятся, команда использует следующий порядок:

1. Проверенное поведение живого proxy API, затем его актуальная web-документация — для сетевого контракта.
2. Корневое ТЗ — для поведения продукта.
3. Актуальная Figma — для UI и показанных состояний.
4. Актуальные критерии успешного выполнения — для архитектуры и учебной приёмки.
5. Старые файлы `Diploma/screens`, подсказки и примеры — только если они не противоречат пунктам выше.

Расхождение не разрешается «на глаз»: оно записывается в [журнал решений](./08-решения-и-риски.md), после чего решение подтверждает команда или наставник.

## Правила актуализации

- В каждом документе фиксируется не значение секрета, а только имя переменной или заголовка.
- Изменение API сначала отражается в `03-api.md`, затем в DTO и тестах контракта.
- Изменение пользовательского сценария сначала отражается в `01-продукт-и-требования.md` и тест-плане.
- Изменение Figma сначала отражается в `04-ui-ux.md` и дизайн-токенах ресурсов.
- Закрытая задача сохраняет исходный ID из декомпозиции, чтобы требования, PR и тесты можно было связать.
