# UI/UX-спецификация

## 1. Источник дизайна

Единственный источник точных визуальных значений — [Figma проекта](https://www.figma.com/design/2xNhuofNp4bedjPLoQdBfC/%D0%94%D0%B8%D0%BF%D0%BB%D0%BE%D0%BC%D0%BD%D1%8B%D0%B9-%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82--Copy-?node-id=0-1&p=f&t=Jx4VVgkNreueEhI9-0).

Вводный материал указывает страницы:

- `Light Mode` — все экраны светлой темы;
- `Dark Mode` — все экраны тёмной темы;
- `Components design` — UI Kit и цветовая палитра;
- `Icon store` — исходник иконки приложения.

Публичный canvas проверен 11.08.2026: доступно более 45 кадров со сценариями. Анонимный просмотр не предоставляет Inspect/Dev Mode и сырой экспорт variables, поэтому значения ниже являются подтверждённым рабочим набором, но перед ресурсным PR UI-владелец повторно сверяет их в авторизованном Inspect. Точные dark-варианты нельзя выводить простым инвертированием — они берутся со страницы `Dark Mode`.

## 2. Экранный состав

### Корневые вкладки

1. Поиск вакансий; подпись вкладки в текущем макете — «Главная».
2. Избранное.
3. Команда.

### Экраны поверх нижней навигации

1. Детали вакансии.
2. Настройки фильтра.
3. Выбор отрасли.
4. Место работы — stretch.
5. Выбор страны — stretch.
6. Выбор региона — stretch.

Подтверждённые кадры включают:

- главную до поиска, ввод с клавиатурой, загрузку, результат и дозагрузку;
- «Таких вакансий нет», «Нет интернета», «Ошибка сервера» и ошибку списка;
- настройки фильтра, место работы, страну, регион, отрасль, поиск/пустой результат/loading/error внутри каталогов;
- детали loading/content, favorite state, системный share sheet и «Вакансия не найдена или удалена»;
- избранное list/empty/error;
- команду с заголовком «Над приложением работали».

## 3. Общие компоненты

До разработки экранов создаются и переиспользуются:

- top app bar с заголовком, back, filter, share и favorite variants;
- BottomNavigationView с тремя пунктами и active/inactive состояниями;
- поисковое поле с hint и clear-кнопкой;
- карточка вакансии;
- контейнер логотипа и placeholder;
- полноэкранный progress;
- footer progress для пагинации;
- empty/error/no-network placeholder;
- primary bottom button («Применить», «Выбрать»);
- строка настройки с текстом, выбранным значением, стрелкой и clear-action;
- checkbox «Не показывать без зарплаты»;
- radio/selection row отрасли;
- типографика HTML-описания и маркированных навыков.

Карточка вакансии должна быть одной UI-моделью/компонентом для поиска и избранного. Различия поведения задаются callback, а не копированием layout.

## 4. Контракт тем и ресурсов

- Обе темы наследуются от `Theme.MaterialComponents.DayNight.NoActionBar`.
- Компоненты используют семантические ресурсы (`colorBackground`, `colorOnSurface`, `textPrimary` и т.п.), а не raw hex в layout.
- Light/dark значения лежат в `values/colors.xml` и `values-night/colors.xml` либо эквивалентных theme attributes.
- Строки, `dp`, `sp`, shape, selector и vector drawable вынесены в ресурсы.
- Не допускается tint, несовместимый с одной из тем.
- Legacy icon создаётся из `Icon store`; при наличии материалов также подготавливается adaptive icon без изменения исходной композиции.

### Чек-лист извлечения токенов из Figma

| Группа | Что зафиксировать |
|---|---|
| Цвета | background, surface, primary/blue, primary variant, text primary/secondary, icon, divider, error, placeholder. |
| Типографика | семейство, weight, size, line height для H1/H2/body/caption/button. |
| Геометрия | экранные поля, вертикальные интервалы, высота toolbar/input/button/card, corner radius, stroke. |
| Состояния | default/pressed/selected/disabled/focused/error для полей, кнопок, checkbox/radio и bottom nav. |
| Графика | логотип placeholder, empty/error illustrations, иконки навигации, app icon. |

## 5. Спецификация по экранам

### Поиск

- App bar: заголовок и иконка фильтра; иконка имеет обычное и подсвеченное состояние.
- Поле: hint при пустом значении, clear при непустом.
- Тело взаимоисключающе показывает initial, fullscreen loading, content, empty, no-network или server-error.
- Content включает количество найденных вакансий, RecyclerView и footer loader.
- Карточка не меняет высоту хаотично при отсутствии опциональных полей; пустые строки скрываются.
- После ошибки следующей страницы список не перекрывается полноэкранным placeholder.

### Настройки фильтра

- Toolbar с back и условной кнопкой «Сбросить».
- Строка отрасли показывает выбранное название и возможность очистить только это значение, если такая action присутствует в макете.
- Поле зарплаты использует цифровую клавиатуру, hint и clear.
- Checkbox отражает сохранённое значение.
- «Применить» расположена внизу и видна по критериям при наличии хотя бы одного параметра.

### Выбор отрасли

- Поле локального поиска с clear.
- Один выбранный элемент; выбор визуально однозначен в обеих темах.
- Кнопка «Выбрать» видна только после выбора.
- Ошибка загрузки каталога не оставляет пустой экран.

### Детали

- Toolbar: back, share, favorite state.
- Контент прокручивается как единое целое.
- Информация с отсутствующим значением скрывается вместе с label/разделителем.
- Адрес заменяется регионом при отсутствии address.
- HTML сохраняет базовые абзацы, переносы и списки.
- Email и телефон визуально распознаются как интерактивные.
- Favorite меняет состояние сразу, а при ошибке хранения откатывается с сообщением.

### Избранное

- App bar и список карточек согласованы с поиском.
- Empty и database-error различимы.
- Отсутствие сети не переводит непустой локальный список в ошибку.

### Команда

- Статический список содержит ровно трёх участников, согласованные имена и роли.
- Не показывать условные названия `UI`, `BE-1`, `BE-2` в релизной сборке.

## 6. Доступность и устойчивость

- Все icon-only кнопки имеют `contentDescription`.
- Декоративные изображения не озвучиваются.
- Touch target интерактивных элементов — не менее 48×48 dp, если макет не требует более крупный.
- Контраст и читаемость проверяются отдельно для обеих тем.
- Текст не обрезается при системном font scale 1.3; длинные названия вакансий, компаний и отраслей проверяются тестовыми данными.
- Для RecyclerView сохраняется позиция при возврате с деталей.
- Клавиатура не перекрывает нижнюю кнопку; back сначала закрывает клавиатуру по стандартному Android-поведению.
- Системные chooser запускаются только при наличии подходящего приложения; отсутствие handler не приводит к crash.

## 7. UI-review каждого PR

К PR прикладываются:

1. Скриншот или короткое видео реализованного сценария.
2. Светлая и тёмная темы на одном и том же состоянии.
3. Ссылка на конкретный Figma node, а не только на корень файла.
4. Перечень намеренных отличий, если они есть.
5. Проверка loading/content/empty/error для соответствующего экрана.

UI-владелец подтверждает визуальную часть, а владелец фичи — корректность состояния и данных.
