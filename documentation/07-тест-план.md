# План тестирования

## 1. Цель и уровни

Тестирование подтверждает требования, устойчивость к неполным данным и отсутствие деградации после командных merge.

| Уровень | Что проверяет | Инструмент/подход |
|---|---|---|
| Unit | formatter, mapper, query builder, debounce, pagination reducer, interactors/ViewModels | JUnit, coroutine test, fakes. |
| Data integration | DAO/Room, SharedPreferences repository, repository с MockWebServer | in-memory Room, MockWebServer. |
| UI/instrumentation | критические переходы и состояния | Compose UI tests; Espresso/FragmentScenario для NavHost и BottomNavigationView. |
| Manual | соответствие Figma, темы, системные chooser, реальные сеть/offline | эмулятор/устройство. |
| CI/regression | сборка, detekt, все unit/integration tests | GitHub Actions на каждый PR. |

## 2. Матрица окружений

- Android 8.0 / API 26 — минимальная версия.
- Одна актуальная стабильная версия Android.
- Малый portrait-экран и стандартный phone.
- Light и dark.
- Font scale 1.0 и 1.3.
- Сеть: online, offline до запроса, потеря сети во время запроса, медленная сеть.
- Локальные данные: пустая и непустая Room, сохранённые фильтры, удалённая на сервере избранная вакансия.

## 10. Release smoke

Перед формальным PR в `main` один участник выполняет сценарий целиком, второй повторяет на другой версии Android:

1. Запуск → поиск → следующая страница.
2. Фильтр отрасли/зарплаты → Apply → новый результат.
3. Открыть детали → share → добавить в избранное.
4. Отключить сеть → открыть список и сохранённые детали.
5. Удалить из избранного → убедиться в синхронизации.
6. Открыть «Команда».
7. Повторить ключевые экраны в dark theme.

Критический дефект блокирует release: crash, утечка секрета, неработающий основной сценарий, потеря избранного, неверный API contract или невозможность сборки.
