# Документация проекта

Этот каталог — единая документация Android-приложения: от базовой структуры до поиска, деталей, локального избранного и фильтров по отрасли, зарплате и месту работы.

## Состав

1. [Источники и приоритеты](./00-источники.md) — откуда взяты требования и как разрешать расхождения.
2. [Продукт и требования](./01-продукт-и-требования.md) — границы MVP, сценарии, состояния экранов и нефункциональные требования.
3. [Архитектура](./02-архитектура.md) — технологические решения, слои, пакеты, навигация и правила обработки данных.
4. [Контракт API](./03-api.md) — актуальные endpoint, DTO, авторизация, ошибки и безопасная настройка секрета.
5. [UI/UX-спецификация](./04-ui-ux.md) — состав макетов, UI-компоненты, состояния и правила переноса дизайна.
6. [Декомпозиция на трёх участников](./05-декомпозиция.md) — микрозадачи, оценки, зависимости, владельцы и итерации.
7. [Процесс разработки](./06-процесс-разработки.md) — GitHub Issues, ветки, PR, ревью и критерии готовности.
8. [План тестирования](./07-тест-план.md) — проверки требований, уровни автоматизации и регресс.
9. [Решения, риски и открытые вопросы](./08-решения-и-риски.md) — принятые трактовки спорных мест ТЗ.
10. [Описание первой итерации ревью](./09-iteration-1-review.md) — готовый каркас PR по Epic 0: выполненный scope, backlog, оценки, фактическое время, внутреннее ревью и CI.
11. [Описание второй итерации ревью](./10-iteration-2-review.md) — PR-diff только по Epic 1–5: scope, план/факт, acceptance, QA и внутреннее ревью.

## Ключевые решения

| Область | Решение |
|---|---|
| Команда | Три участника: UI/дизайн-разработчик и два Android-разработчика data/domain. Backend-сервис уже предоставлен, поэтому «бекенд» здесь означает клиентские Data/Domain-интеграции. |
| Объём второй итерации | Epic 1–5: поиск, пагинация, детали, избранное офлайн, экран команды, фильтры по отрасли/зарплате и месту работы. |
| Базовый scope | Epic 0 уже принят в `main`; PR #10 не должен показывать его как новое изменение. |
| UI | XML-контейнер с NavHost/BottomNavigationView; содержимое Fragment через ComposeView и Composable; MaterialTheme со светлой и тёмной схемами по Figma. |
| Архитектура | Single Activity, Navigation Component, MVVM, Clean Architecture, Koin, Retrofit, Room, SharedPreferences, Coroutines, StateFlow. |
| API | `https://android-diploma.education-services.ru`; живой сервер принимает `Authorization: Bearer <token>` (проверено 11.08.2026). |
| Безопасность | Значение токена не хранится в Git и не приводится ни в одном документе. |

## Порядок формальной сдачи

| Итерация | Содержание |
|---|---|
| 1 | Только Epic 0: настройка проекта и окружения, общая инфраструктура, темы, граф навигации, заглушки и BottomNavigationView. |
| 2 | Только diff Epic 1–5: поиск, команда, детали, избранное и фильтры, включая место работы. |

Epic 0 относится только к первой итерации. Экран команды и Epic 1–5 относятся ко второй.

Перед сдачей второй итерации лид заполняет фактические данные в [её checklist](./10-iteration-2-review.md); незаполненные часы, ссылки или approvals нельзя заменять предположениями.

## Как начать

1. Командой подтвердить решения и открытые вопросы из [08-решения-и-риски.md](./08-решения-и-риски.md).
2. Подставить реальные имена участников вместо ролевых обозначений `UI`, `BE-1`, `BE-2`.
3. Перенести задачи из [05-декомпозиция.md](./05-декомпозиция.md) в GitHub Issues/Projects, сохранив ID, зависимости и оценки.
4. Выполнить Epic 0 целиком до параллельной разработки фич.
5. Сверять каждый UI-PR с актуальным Figma-файлом в обеих темах.

Документация проверена по источникам 11 августа 2026 года. При изменении API, ТЗ или Figma сначала обновляется этот каталог, затем код.
